# Ежедневник — Telegram Mini App

Это веб-версия твоего приложения из `DailyPlanner`, сделанная специально для Telegram.
Дизайн и поведение повторяют мобильное приложение: главный экран, свайпы по дням и
неделям, настройки, готовое расписание ТГЭ-26-2, статистика, управление днями,
незапланированные события, календарь и игра с котиком.

Проект находится в папке:

```
C:\Users\Игорь\Desktop\DailyPlanner\telegram-miniapp
```

---

## Что уже готово

- Все экраны и функции мобильного приложения, кроме системных уведомлений
  (почему — см. раздел «Ограничение: уведомления»).
- Сохранение данных в Telegram CloudStorage.
- Резервное сохранение в localStorage (если CloudStorage недоступен).
- Готовый шаблон настроек `НАСТРОЙКИ.txt`.
- Простой локальный сервер без npm-зависимостей.
- Скрипт, который сам настраивает кнопку меню и команду `/start` у бота.

## Шаг 1. Заполни `НАСТРОЙКИ.txt`

Открой файл:

```
telegram-miniapp\НАСТРОЙКИ.txt
```

### 1.1. Получи токен бота

1. Открой Telegram.
2. Найди `@BotFather`.
3. Отправь команду `/newbot`.
4. Придумай имя бота (например, «Мой ежедневник»).
5. Придумай username, он должен заканчиваться на `bot`
   (например, `my_daily_planner_bot`).
6. BotFather пришлёт токен вида:

```
123456789:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

7. Вставь токен в `НАСТРОЙКИ.txt`:

```ini
BOT_TOKEN=123456789:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

> Токен — это пароль от бота. Никому его не отправляй и не выкладывай в интернет.
> Если токен случайно попал в чужие руки, в BotFather выполни `/revoke` и получи новый.

### 1.2. Укажи username бота

```ini
BOT_USERNAME=my_daily_planner_bot
```

Без `@`. Это необязательное поле, нужно только для удобства.

### 1.3. Публичный адрес

`PUBLIC_URL` нужно заполнить после того, как приложение будет опубликовано.
Telegram принимает только HTTPS-адреса.

Пример:

```ini
PUBLIC_URL=https://my-planner.netlify.app
```

Пока адреса нет — оставь поле пустым и переходи к шагу 2.

## Шаг 3. Получи HTTPS-адрес

Для Telegram нужен публичный HTTPS-адрес. Выбери один из вариантов.

### Вариант А. Быстро и временно — Cloudflare Tunnel

Подходит, чтобы сразу открыть приложение на телефоне. Пока компьютер и туннель
включены — приложение работает.

1. Скачай `cloudflared` для Windows:
   https://github.com/cloudflare/cloudflared/releases
2. Запусти сервер:

```powershell
cd "C:\Users\Игорь\Desktop\DailyPlanner\telegram-miniapp"
node server.js
```

3. Во втором окне PowerShell запусти туннель:

```powershell
cloudflared tunnel --url http://localhost:3000
```

Если команда `cloudflared` не найдена, открой папку с `cloudflared.exe` и запусти:

```powershell
.\cloudflared.exe tunnel --url http://localhost:3000
```

4. В консоли появится ссылка вида:

```
https://random-words-1234.trycloudflare.com
```

5. Вставь её в `НАСТРОЙКИ.txt`:

```ini
PUBLIC_URL=https://random-words-1234.trycloudflare.com
```

6. В третьем окне PowerShell выполни:

```powershell
node setup-bot.js
```

7. Открой своего бота в Telegram и нажми кнопку меню «Открыть ежедневник».

**Важно:** временный адрес Cloudflare меняется после каждого перезапуска туннеля.
Если адрес изменился — обнови `PUBLIC_URL` и снова выполни `node setup-bot.js`.

### Вариант Б. Постоянно и бесплатно — Netlify Drop

Подходит, если не нужен сервер и достаточно статического сайта. Данные всё равно
хранятся в Telegram CloudStorage, поэтому сервер для них не нужен.

1. Открой https://app.netlify.com/drop
2. Перетащи в окно папку:

```
telegram-miniapp\public
```

Именно папку `public`, а не весь проект.

3. Netlify выдаст постоянный адрес вида:

```
https://random-name-123456.netlify.app
```

4. Вставь адрес в `НАСТРОЙКИ.txt`:

```ini
PUBLIC_URL=https://random-name-123456.netlify.app
```

5. Один раз выполни на компьютере:

```powershell
cd "C:\Users\Игорь\Desktop\DailyPlanner\telegram-miniapp"
node setup-bot.js
```

6. Открой бота и нажми кнопку меню.

При статическом размещении кнопка меню работает, но команда `/start` не будет
отвечать сообщением: для ответа нужен сервер с вебхуком (вариант В). На само
приложение это не влияет.

### Вариант В. Постоянно, с сервером — Render (рекомендуется)

Подходит, если хочешь, чтобы бот отвечал на `/start` и сам настраивал вебхук.
В проекте уже есть файл `render.yaml`, поэтому Render сам создаст бесплатный
Web Service с нужными настройками.

#### В.1. Подготовь GitHub

1. Создай новый репозиторий на GitHub, например `daily-planner-miniapp`.
2. Загрузи в него **содержимое** папки `telegram-miniapp` так, чтобы в корне
   репозитория были `package.json`, `server.js`, `public/` и `render.yaml`.
3. Файл `НАСТРОЙКИ.txt` не загружай: в нём токен, и он уже указан в `.gitignore`.

Если делаешь через Git в PowerShell:

```powershell
cd "C:\Users\Игорь\Desktop\DailyPlanner\telegram-miniapp"
git init
git add .
git commit -m "Telegram Mini App"
git branch -M main
git remote add origin https://github.com/ТВОЙ_АККАУНТ/daily-planner-miniapp.git
git push -u origin main
```

#### В.2. Удали старый сервис, если он не нужен

Если `bonch-checkin` больше не нужен:

1. Открой Render Dashboard.
2. Выбери сервис `bonch-checkin`.
3. Settings → внизу **Delete Web Service**.
4. Подтверди удаление.

Репозиторий `oblakolast/bonch-checkin` при этом не удаляется — удаляется только
запущенный сервис. Если старый сервис ещё нужен, просто оставь его и создай
новый: на бесплатном тарифе можно иметь несколько сервисов, но часы использования
общие.

#### В.3. Создай новый сервис через Blueprint

1. Открой https://dashboard.render.com
2. Нажми **New +** → **Blueprint**.
3. Подключи GitHub и выбери новый репозиторий `daily-planner-miniapp`.
4. Render прочитает `render.yaml` и покажет сервис `daily-planner-miniapp`,
   план **Free**.
5. Он попросит заполнить `BOT_TOKEN` — вставь токен из `@BotFather`.
6. Нажми **Apply** / **Create** и дождись окончания деплоя.

`PUBLIC_URL` указывать не нужно: сервер возьмёт адрес Render автоматически из
переменной `RENDER_EXTERNAL_URL`. `WEBHOOK_SECRET` Render сгенерирует сам,
а `AUTO_SET_WEBHOOK=yes` уже прописан в `render.yaml`.

#### В.4. Проверь деплой

1. Открой сервис в Render → **Logs**.
2. Там должно быть примерно так:

```
📅 Ежедневник — Telegram Mini App
🌐 Публично: https://daily-planner-miniapp.onrender.com
🤖 Бот: @my_daily_planner_bot
✅ Кнопка меню «Открыть ежедневник» установлена.
✅ Вебхук установлен.
```

3. Открой в браузере:

```
https://ИМЯ-СЕРВИСА.onrender.com/health
```

Должен вернуться ответ:

```json
{"ok":true,"service":"daily-planner-miniapp"}
```

4. Открой бота в Telegram и нажми кнопку меню. Команда `/start` тоже должна
   ответить кнопкой «Открыть ежедневник».

#### Если создаёшь вручную, без Blueprint

1. **New +** → **Web Service**.
2. Подключи репозиторий `daily-planner-miniapp`.
3. Настройки:

```
Name: daily-planner-miniapp
Runtime: Node
Build Command: npm install
Start Command: npm start
Plan: Free
```

4. В **Environment** добавь:

```
BOT_TOKEN=токен_бота
WEBHOOK_SECRET=длинная_случайная_строка
AUTO_SET_WEBHOOK=yes
NODE_VERSION=22
```

`PUBLIC_URL` можно не добавлять — сервер возьмёт `RENDER_EXTERNAL_URL`.
Если хочешь указать вручную, добавь:

```
PUBLIC_URL=https://имя-сервиса.onrender.com
```

5. Нажми **Create Web Service** и проверь логи и `/health`.

На бесплатном тарифе Render сервис «засыпает» после простоя. Первое открытие
после паузы может занять 30–60 секунд. Это нормально. Данные при этом не
теряются: они хранятся в Telegram CloudStorage, а не на диске Render.

1. Открой своего бота по ссылке:

```
https://t.me/my_daily_planner_bot
```

2. Нажми «Открыть» или кнопку меню слева от поля ввода.
3. Приложение откроется внутри Telegram.
4. Заполни расписание:
   - «Настройки» → «Расписание ТГЭ-26-2» — готовое расписание группы;
   - или «Расписать неделю» / «Расписать две недели» — вручную.
5. Сделай свайп по дню или неделе, проверь статистику и игру.

Данные из старого Expo-приложения автоматически не переносятся: у него было
другое хранилище на телефоне. Расписание нужно один раз настроить заново —
например, кнопкой «Расписание ТГЭ-26-2».

Если кнопка меню не появилась:

- убедись, что `PUBLIC_URL` начинается с `https://`;
- проверь, что адрес открывается в браузере телефона;
- снова выполни `node setup-bot.js`;
- закрой и снова открой чат с ботом (иногда Telegram кэширует меню).

## Где хранятся данные

- Основные данные (расписание, правки дней, события) — в **Telegram CloudStorage**.
- Они привязаны к твоему Telegram-аккаунту и боту, поэтому доступны с телефона
  и с другого устройства с тем же аккаунтом.
- Рекорд игры хранится отдельно, тоже в CloudStorage.
- В обычном браузере используется localStorage — это резервный режим.
- На сервере база данных не нужна: сервер только отдаёт файлы приложения и,
  при желании, принимает вебхук бота.

Если очистить данные бота в Telegram, облачные данные тоже могут удалиться.
Сделай резервную копию, если расписание очень важное (например, сфотографируй
экраны или сохрани текст расписания).

## Ограничение: уведомления

В мобильном Expo-приложении были локальные уведомления. Telegram Mini App
**не может** планировать системные уведомления на телефоне: у веб-приложения
внутри Telegram нет доступа к локальным уведомлениям iOS/Android.

Поэтому в этой версии уведомлений нет. Всё остальное — расписание, правки,
статистика, игра — работает.

Если уведомления нужны, их можно сделать через бота: сервер по расписанию
отправляет сообщение в Telegram. Для этого нужен постоянно работающий сервер
и дополнительная настройка. В текущей версии этого нет.

## Частые проблемы

### «Открывается пустой белый экран»

- Проверь, что открываешь именно `PUBLIC_URL`, а не путь к папке на компьютере.
- Открой адрес в браузере: там должна появиться страница «Ежедневник».
- Если размещаешь на Netlify/GitHub Pages, загружай содержимое папки `public`,
  чтобы `index.html` был в корне сайта.
- Посмотри ошибки в консоли браузера (F12 → Console).

### «Кнопка меню ведёт на старый адрес»

- Обнови `PUBLIC_URL` в `НАСТРОЙКИ.txt`.
- Снова выполни `node setup-bot.js`.
- Перезапусти Telegram или открой чат заново.

### «Данные не сохраняются»

- Открывай приложение через бота в Telegram, а не через обычный браузер.
- В браузере данные сохраняются в localStorage и не попадают в Telegram.
- В Telegram CloudStorage может быть недоступен при очень плохой сети;
  приложение попробует сохранить данные локально.

### «Не работает /start»

- Команда `/start` отвечает только при работающем сервере с вебхуком
  (вариант В).
- При статическом размещении (Netlify, GitHub Pages) кнопка меню работает,
  а `/start` может не отвечать — это ожидаемо.

### «Ошибка 404 на Netlify»

- Проверь, что `index.html` лежит в корне опубликованного сайта.
- Не загружай всю папку `telegram-miniapp`: только `public`.

## Безопасность

- Не отправляй `НАСТРОЙКИ.txt` никому.
- Не коммить его в Git: файл уже в `.gitignore`.
- При размещении на Render используй переменные окружения, а не файл.
- Если токен утёк — BotFather → `/revoke` → получи новый токен и обнови настройки.
- `WEBHOOK_SECRET` придумай длинным и случайным, не используй простые слова.
